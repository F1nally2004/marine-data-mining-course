## 2. 状态与消息合同

`SourceState` 构造时只接收source_id、配置、固定源名单、时钟、随机流和outbox。没有原始完整DataFrame或oracle引用。每次采集以输入事件推进本地状态。

`Coordinator` 构造时只接收方法、配置、outbox和已送达消息回调。不能持有SourceState指针。

`Snapshot` 至少包括 `(window_id, query_id, roster_version, epoch_by_source, request_id, frozen_S, exact_K_by_source, ack_prefix_by_source)`。S、K冻结后不可原地修改；后续全局状态使用另一份可增集合。

`CoverageProof` 类型为 `COUNT_EXACT | LIST_EXACT | POLY_PROBABILISTIC`。来源关联的精确K与概率覆盖证明分开保存。全局确认类型取所有依赖证明中的最弱类别。

单独维护 `known_identity_set`、`published_count`、`last_exact_numeric_anchor`。全部SEAL后根据源基数和精确K计算LB/UB；两界相等可以直接COUNT_EXACT，不要求S已包含全部身份。此后新身份不能在这个已确定数值上再次+1。

源封闭状态：`OPEN -> SEALED`；违约后 `INVALIDATED`，仅有效外部重新封闭可进入新epoch。

协调器窗口状态：`PROVISIONAL -> CHECKING -> EXACT_FINAL/HASH_FINAL`；违约或确认后新身份转为`REOPENED`。超时H仅生成评估状态UNCONFIRMED，不产生完成证明。

主要消息为 `DATA, SEAL, CHECK_REQUEST, EXACT_IDS, HASH_PROOF, EXACT_FALLBACK_REQUEST, REOPEN, ID_BATCH`。每一帧带48字节公共头；请求ID加源/窗口/epoch唯一绑定快照。

## 3. 核心处理伪代码

```python
on_data_or_exact_ids(source, window, epoch, ids):
    validate_scope_and_epoch()
    insert_into_exact_K(source, ids)
    add_verified_ids_to_global_S(ids)
    refresh_count_bounds_and_numeric_anchor()  # 数值确认后禁止重复+1
    publish_revision_if_changed(cause)
    refresh_count_exact_coverage()
    maybe_confirm_if_all_sources_sealed_and_covered()

on_all_seals_available(window):
    refresh_count_bounds_and_numeric_anchor()
    if count_bounds_collapsed():
        publish_exact_numeric_final()
        return
    freeze_one_snapshot()
    for source in sources_not_covered_by_exact_count:
        send_check_request_via_network(ack_prefix, snapshot_size)

source_handle_check(req):
    validate_local_seal_and_request()
    P = distinct_ids_in_local_closed_log_after(req.ack_prefix)
    if exact_mode_or_exact_wire_bytes_not_larger_or_len(P) > req.snapshot_size:
        send_exact_ids(P)
    else:
        bf = build_bloom(P, deterministic_size_rule(req.snapshot_size, len(P)))
        r = independent_uniform_field_point_after_snapshot()
        send_hash_proof(len(P), bf, r, set_fingerprint(P, r))

on_hash_proof(proof):
    validate_request_scope_epoch_and_fragments()
    V = {x for x in frozen_S if proof.bloom.contains(x)}
    if len(V) == proof.set_size and fingerprint(V, proof.r) == proof.value:
        mark_source_probabilistically_covered(proof.error_bound)
        # 不将V写入exact_K，不把HASH升级成EXACT
    else:
        request_one_exact_fallback_via_network()
    maybe_confirm_if_all_sources_sealed_and_covered()
```

网络超时重发同一request_id，源缓存同一P/参数/随机点的响应；不能因状态变动偷偷更换P。真实网络仍继续传输原始报文，不因发了身份元数据免费取消积压。

## 5. 实施顺序与验收

1. 先做schema、wire、snapshots、精确源状态、事件循环；通过连续前缀、错epoch、空源和分片测试。
2. 实现PAYLOAD_BARRIER、UPSTREAM_COUNT_ONLY、FULL_ID_MANIFEST和SEALED_DIFF_EXACT。用最小多源反例逐条人工验证计数及确认时刻。
3. 实现WM/TIMER及ID_STREAM强基线，确保所有方法相同临时发布、晚到修订和网络收费语义。
4. 实现独立Bloom与有限域指纹，再接入HASH版本；小域碰撞只作诊断，生产版本严格保留HASH类别。
5. 接入空间多源、FIFO/WFQ、丢包与CPU校准；所有额外流量真实影响数据到达。
6. 运行8条smoke；任一正确性或泄漏测试失败，修实现并重跑技术检查，保留失败日志。参数方案如需改变，另起版本，不能覆盖已冻结结果。
7. 执行replay/pressure/faults矩阵，逐run追加输出；报告全部结果，无人工筛选“成功”配置。
